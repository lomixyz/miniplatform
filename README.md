# MiniPlatform — Chat & Games Web App

A small chat-and-games web app inspired by mig66: real-time chat rooms, a virtual gift/coin economy, a leveling system, a playable multiplayer UNO game, a mobile-app-style navigation shell (home screen, room browser, participants panel, alerts/emails/friends), and a staff/admin role system. Original branding and UI — not a copy of mig66's name or graphics.

## Features

- **Chat only ever shows what's said while you're actually in the room** — for everyone, no exceptions: Staff, Global Admin, every role, all the same. No chat history is ever fetched or replayed when you genuinely enter a room (clicking it from Room Browser, or coming back after actually leaving) — the message pane starts fully blank and only fills with whatever comes in live from that point forward. But clicking things that just point back at the room you're ALREADY in — its tab pill, its quick-icon, navigating to Home and back — is not treated as re-entering: those leave the chat exactly as it was, since you never actually left. Only an explicit Leave Room (or a kick/bump/idle-timeout) followed by rejoining clears it again. `GET /rooms/:id/messages` (unused by the client now, but kept for any future scrollback feature) still requires active membership and returns 403 with no content otherwise, checked fresh on every call — being logged in, or having been a member before and since left, was never enough.
- **Ambient chat / test population** — 100 seeded accounts (real first names, gender assigned to match, flagged `is_bot` internally so they can never be confused with or displace a real login) sit as active members of every room and periodically chat with each other — casual, room-appropriate small talk (general chat in Lobby, game banter in UNO Arena, relaxed talk in Chill Zone), posted as genuine back-and-forth exchanges every 20–75 seconds while the server is running (see `src/chatbots.js`). A multi-hour conversation backlog is pre-seeded too, so every room already looks lived-in the moment you open it, even before the live simulator has had time to add more.
- **Redesigned auth screens** — Login ("User ID" + "Secret Code", Remember me, Forgot Code) and Create Account ("Join the community": User ID, Email ID, Secret Code + Confirm Code with show/hide toggles, Gender, Country, optional Referrer User ID, and a Terms of Use checkbox) with MiniPlatform's own branding. Everything entered is real and stored — email, gender, country, and the referrer link — with server-side validation (Confirm Code must match, referrer must exist, terms must be agreed to). There's no mail server behind this build, so "Forgot Code" is a direct in-app reset (confirm your User ID + Email ID on file, then set a new Secret Code — no emailed code), and "Activate Account" is just an info screen explaining accounts are live the moment Create Account succeeds.
- **Accounts & seven independent roles** — register/login with sessions. Roles are independent flags (`is_staff`, `is_global_admin`, `is_mentor`, `is_merchant`, `is_exec_board`, `is_country_rep`, `is_elite`) and an account can hold any combination at once (e.g. the seeded `admin` account is staff AND global admin):
  - **Staff** manages the Admin Panel — searching for users, granting/revoking any of the seven roles, promoting a user to Global Administrator, and setting a user's level directly.
  - **Global Administrator** is a room-moderation role — it can kick members out of a room (see below) but does **not** get Admin Panel access, even if it's the only role the account has.
  - **Executive Board**, **Country Representative**, and **Elite User** are community-recognition roles (shown grouped under "Staff & Admin" on the Members screen alongside Admin/Staff) — granted the same way as any other role, with their own color/badge.
  - **Mentor** and **Merchant** are granted the same way (checkboxes in the Admin Panel) — role flags with their own color/badge, and both can give coins to users (see below).
- **Search-first Admin Panel** — the panel doesn't dump every registered user (unusable and slow once you have hundreds or thousands of accounts). Staff type a username, search, and get up to 20 matching accounts to manage.
- **Give Coins (Staff, Mentor, Merchant)** — a separate, lighter panel (nav drawer → 🪙 Give Coins) for handing coins to any user as a reward or prize, without needing Admin Panel access. Search by username, enter an amount, and give it — the recipient's balance updates live in their browser immediately if they're online, plus they get a system toast and a saved Alert ("🪙 username gave you N coins!"). Available to Staff, Mentor, and Merchant accounts alike; the server re-checks the role on every request.
- **Role-colored usernames** — a Staff member's name renders as a **green → blue → red gradient** everywhere (chat, participants panel, admin panel, Members, Leaderboards), with a 👑 badge, and this is the one color nothing can override. Every other role has its own color too — Global Administrator **yellow** with 🛡️, Executive Board **indigo** with 🎖️, Country Representative **tan/brown** with 🌐, Elite User **teal** with 🏅, Mentor **red** with 🧭, Merchant **purple** with 💼 — but **a purchased Color Shop color now outranks all of these** (Staff excepted): buy a color and your name shows in that color instead of your role's, while the role badge/icon next to your name still shows so your permission level stays visible. With no purchased color, role priority is Executive Board > Global Admin > Country Rep > Elite > Mentor > Merchant.
- **Levels & XP** — every account has an XP total and a derived level (starts at Lv.1, each level needs progressively more XP: 100, 150, 200, ...). XP is earned by chatting (+2), sending a gift (+5), receiving a gift (+5), triggering a gift shower (+10), picking a voucher (+5), winning UNO (+50), and playing a finished UNO game (+10). Level, an animated XP bar on the Home screen, and a level-up toast are all shown live. A user's current level is tagged in brackets — `username [level]` — everywhere their name appears: joining/leaving a room, being kicked, and sending/receiving gifts.
- **Staff can set a user's level directly** — in the Admin Panel, every row has a level control (−, a number field, +, and "Set") so Staff can bump someone up (or down) as a reward or correction. It writes straight to that user's xp and, if they're online right now, updates their level and XP bar live in their browser with no refresh needed.
- **Home screen** — a profile card (colored-initial avatar, username, online-status dot, level pill, editable one-line bio, XP progress bar), quick-action buttons for Alerts/Emails/Friends with unread badges, a "Current Chat Rooms" list of recently visited rooms with live member counts, and a friends list with online status.
- **Room Browser** — search rooms by name, browse Recent / Official / Other rooms as cards (colored icon, "X/Y in room" count, official ✅ badge), star a room to favorite it, or create a new room. Clicking a room's colored letter icon is what enters it.
- **Chat screen** — a room tab bar for quickly switching between rooms you have open, a bottom action sheet (⋮ button) with Participants / Check Balance / Send Gift / Clear Chat / Leave Room, and bracket-formatted system/gift/voucher messages matching the reference UI. The room you're in survives a page refresh — you land back in the same chat instead of being dropped to the Home screen.
- **Persistent room membership** — once you've entered a room, you stay listed as a member no matter what: a page refresh, a brief network drop, or switching to view another room never removes you or posts a "has left" message. The only ways to leave are explicit — clicking **Leave Room**, being **kicked**, or going **idle for 5 hours straight** (no chat, gift, pick, or UNO action in that room) — a periodic sweep checks for this every 15 minutes. Each participant shows a small online/offline dot, since "in the room" and "currently connected" are now tracked separately.
- **Participants panel** — a slide-over listing everyone currently in the room (avatar, online dot, name, role color, level as "Lv.N" — no brackets here; brackets are reserved for room-entered/left and gift chat messages, see below — role badge icon). Staff and Global Administrators see "Bump" and "Kick" buttons next to every other member — these work even if that member isn't currently connected, since membership is persistent. Kicking removes them from the room, blocks them from rejoining that room for **10 minutes**, and posts a `name [level] was kicked by name [level] — can't rejoin for 10 minutes` system message; bumping does the same but with a lighter **5-minute** cooldown and softer wording. The removed user gets a toast naming who removed them and how long the cooldown is (or a "removed for inactivity" toast if it was the 5-hour idle timeout, which carries no rejoin cooldown). Both actions are also available as chat commands — `/kick <username>` and `/bump <username>` — with the exact same effect as the panel buttons. The server re-checks the Staff/Global Administrator flag on every kick or bump attempt (button or command), and — independently of the client — refuses any chat message, gift, or rejoin from someone who isn't currently an active member of that room, so a removed user can't keep chatting or gifting from a stale tab. **Staff is immune to kick/bump** — even a Global Administrator can't remove a Staff member from a room (server-enforced; the Kick/Bump buttons don't even render for a Staff target).
- **Entering a room announces you to everyone already there** — `name [level] <role badge> has entered` posts live to everyone currently focused on that room, and the Participants panel updates for them too, the moment you enter (not just for you). This fires the first time you ever become an active member of that room, AND every time you come back after being fully offline for more than ~10 seconds (closed the app, lost connection, came back later) — even though your persistent membership never lapsed, everyone else genuinely saw you disappear and reappear, so it announces again. A quick page refresh, a brief network blip, or switching between room tabs you're already an active member of all stay silent — those aren't a real "away and back."
- **Chat history clears for a user who leaves, logs out, or is removed** — when you explicitly leave a room, log out, or get kicked/bumped/idle-timed-out, your own view of that room's chat is marked cleared. The next time you open that room (after logging back in, or once a kick/bump cooldown expires), you see a blank chat rather than everything that was posted while you were gone — everyone else's history is untouched. A plain page refresh or brief disconnect (no explicit leave) never triggers this — you still see full history exactly as before.
- **A fresh login always starts clean, for every account including Staff/Global Admin** — logging in never auto-opens the last room you were in or replays its chat (unlike a same-session page refresh, which still lands you back where you were, per the point above). Every login also clears the visible chat history for every room you're a member of, immediately — so even if you do open a room right after logging in, it starts blank, not with whatever was posted before you signed back in. The Recent Rooms list on the Room Browser still shows rooms you've visited before as a shortcut, but nothing opens by itself — you have to tap one.
- **Alerts / Notifications** — a full-screen notification list (nav drawer → 🔔 Alerts, or the Home screen quick-action) with a colored icon per type, a bold headline, a gray description line, and a right-aligned timestamp ("21h ago" / "yesterday" / "Aug 30", with the exact date and time underneath). Notifications are created for: a welcome message on registration (📣 blue), receiving a **private** gift — sent directly (gift bar, `/gift <user> <gift>`) or from the Gift Store (🎁 pink), being given coins by Staff/Mentor/Merchant (🪙 orange), and leveling up (🔔 gold). **A `/gift all` gift shower deliberately does not create an Alert** — it already announces itself loudly with a room chat message and the on-screen shower animation, and with several recipients per shower it would otherwise flood everyone's Alerts list; Alerts are reserved for private, 1:1 gifts. Unread ones are highlighted; opening one marks it read and updates the unread badges on the Home screen and nav drawer.
- **Emails (direct messages)** — a real private 1:1 chat separate from room chat: a thread list sorted by most recent message with unread counts, and a full conversation view to read and reply. Messages arrive **live** over Socket.io (no need to reopen the panel to see a new reply), in addition to being saved so a thread reloads fully on open.
- **Friends** — send a friend request by username, accept/decline incoming requests, see outgoing requests, and remove a friend. Friends show live online/offline status on the Home screen and in the Friends panel. Clicking a friend (or the ✉️ button next to them) jumps straight into a private Emails thread with them.
- **Invisible mode (Staff / Global Administrator only)** — from the chat action sheet (⋮ → "Go Invisible"), Staff or a Global Administrator can enter a room without appearing in anyone else's Participants panel. Everyone else's participants list and count behave normally; the invisible moderator still sees the full room (including themself, tagged with a 👻 marker) and can still act (e.g. kick). The permission is re-checked server-side on every toggle, not just hidden in the UI.
- **Voucher / pick-code system** — every active room (at least one person in it) gets an automatic voucher drop every **30 minutes** ("Hurray! A small gift for you. You have 40 seconds to pick the voucher [code] 123456. Type /pick 123456 to get the voucher. (Amount 60 Coins)."). The first person to type `/pick <code>` within the 40-second window wins the coins; a room shows a "voucher expired" message if nobody claims it in time. A room never gets a second voucher while one is still active/unclaimed. **Picking one is private** — it no longer posts a "username picked the voucher" line to the room chat; the picker just gets a toast confirming their win (everyone still sees the original drop and expiry announcements, since those aren't about any one person).
- **Virtual gifts** — every user starts with 1000 coins. Sending a gift deducts coins from the sender and credits the recipient, with a gift message posted to the room chat. Catalog: Rose, Heart, Crown, Rocket, Diamond, Sudan 🇸🇩, Black Diamond 🖤💎, Pink Diamond 💗💎, Coffee, Angel, Bhai, Boss.
- **Gift chat commands**:
  - `/gift all` — a shower to everyone currently in the room: if others are present it's a real transaction (total cost = gift cost × recipient count, deducted from the sender and credited to each recipient) with a `<<🎁*GIFT SHOWER* sender [level] gives a GiftName 🎁 to name1, name2, name3, name4 and N others! Hurray!>>` message; if you're alone in the room it falls back to a free celebratory effect (a burst of gift emojis plus a banner) since there's nobody to actually gift.
  - `/gift all <gift name>` — the same shower, themed to one specific gift (e.g. `/gift all sudan` rains only the Sudan flag 🇸🇩 and gifts everyone present that item).
  - `/gift <username> <gift name>` — sends that specific gift to that user directly from chat (e.g. `/gift lomi sudan`), same as using the gift bar, and posts `<<sender [level] gives a GiftName 🎁 to recipient [level]!>>`.
- **UNO game** — join the in-room lobby, start a game with 2+ players, and play a full UNO match (draw, skip, reverse, +2, wild, +4) in real time. Hands are private to each player; everyone sees card counts and the discard pile. Winning a match increments that player's `uno_wins` counter, which feeds the Leader Board (see Explore below).
- **Nav drawer, redesigned** — a profile card up top (avatar, role-colored name, level, active-status dot, XP and coin totals) followed by My Profile, My Account, Friends, **Explore**, Blog, Game List, Settings, then the existing Rooms/Alerts/Emails/Give Coins/Admin Panel items and Logout — matching the reference app's layout.
- **Explore hub** (nav drawer → 🧭 Explore) — a single screen linking out to every feature below. It, and everything it opens, share one full-screen navigation shell with a back arrow and a back-stack, so drilling down (e.g. Explore → Members → Staff) and returning up works uniformly:
  - **Announcements** — official posts from Staff, newest first, in the same visual style as Alerts. Staff get an inline composer (title + content) right on the screen; anyone can read.
  - **Gift Store** — send a gift to *any* user, not just people in your current room. Search by username (via a new `GET /api/users/search` endpoint, open to any logged-in user, capped to 20 results), pick a gift from the catalog, and send — coins, XP, and the Gift Contest counters update exactly like an in-room gift.
  - **Members** — every role broken into its own group under two sections, "Staff & Admin" (Executive Board, Admin, Country Representative, Staff, Elite User) and "Community" (Mentor, Merchant, Top Level Users — the 10 highest-XP accounts, since it's not a role flag). Tapping a group lists its members with role-colored names.
  - **Leader Board** — top UNO winners, ranked by `uno_wins`.
  - **Legendary Contest** and **Gift Contest** — ranked by lifetime `total_spent` and `gifts_sent_count`. **Simplification note:** these are always-on live rankings rather than the reference app's time-boxed events with periodic resets and separate prize payouts — implementing real contest scheduling/resets/payouts was out of scope for this pass.
  - **Daily Spin** — one free spin every 24 hours per account, weighted toward small coin/XP prizes with rarer bigger ones; shows a live countdown once used and re-enables automatically when the cooldown ends.
  - **Color Shop** — buy a custom username color (8 preset colors, 200–750 coins) that applies everywhere a username with no role badge is shown — chat, the Participants panel, Members, Leaderboards; a Reset option returns it to default for free. A role badge always outranks a purchased color. **Reflects live**: if you're currently in a room, buying (or resetting) a color updates your entry in everyone else's Participants panel immediately, and your very next chat message already carries the new color — no refresh needed for you or anyone else in the room.
  - **Avatar Maker** — pick a frame color, a pet emoji, and a scene emoji for your avatar (all free, applied immediately). **Simplification note:** this is a frame + pet + scene picker rather than the reference app's full layered-outfit/clothing compositor — a true outfit system (garment layers, unlockable items, an inventory) was out of scope for this pass.
  - **Command List** — a reference list of every chat command (`/gift all`, `/gift all <gift>`, `/gift <user> <gift>`, `/pick <code>`, `/kick <user>`, `/bump <user>`) with a one-line description each.
- **My Profile** — a read-only summary of your own account: avatar (with its frame/pet/scene), role-colored username, level & XP, coins, UNO win count, bio, "member since" date, and country. **Country is choose-once**: pick from a flag+name dropdown of ~90 countries and it's saved permanently — the picker disappears and is replaced with a locked "🔒 only Staff can change it now" note. Staff is exempt from the lock: the Admin Panel's user table has its own Country column (dropdown + Set) that can set or overwrite ANY account's country at any time, including one a user already chose.
- **My Account** — change your password (current + new, minimum 4 characters); the seeded `admin` account's password is fixed and can't be changed here.
- **Settings** — quick links to Color Shop, Avatar Maker, My Account, and Logout.
- **Game List** — currently lists UNO; tapping it jumps into the UNO tab of whichever room you have open (or sends you to Rooms first if you're not in one).

## Getting started

Requires **Node.js 22.5 or newer** (uses Node's built-in SQLite module, so there's nothing to compile — no Visual Studio / build tools needed on Windows).

```bash
npm install
npm start
```

Then open http://localhost:3000 in your browser.

**Environment variables** (all optional — safe dev defaults are used if unset). Copy `.env.example` to `.env` and fill in real values before deploying anywhere public:

- `SESSION_SECRET` — signs session cookies.
- `ADMIN_PASSWORD` — password for the two built-in `admin` / `miniplatform` accounts (see below). Change this from the shipped default before deploying.
- `PORT` — defaults to `3000`.

**Permanent data storage on Render (Litestream):** Render's disk is wiped on every redeploy, which used to mean every registered user disappeared after a new push. This is now fixed with [Litestream](https://litestream.io) — a small sidecar process that continuously streams every SQLite write to S3-compatible cloud storage (e.g. Cloudflare R2's free tier) and restores the database from there automatically on boot. No code changes were needed for this — `data/app.db` is used exactly as before; only `start.sh` / `litestream.yml` / `scripts/install-litestream.sh` were added. It only activates when these four env vars are set (locally, or on any host without them, the app just runs against the local file as always):

- `LITESTREAM_BUCKET` — the S3/R2 bucket name.
- `LITESTREAM_ENDPOINT` — the S3-compatible endpoint URL (e.g. `https://<account-id>.r2.cloudflarestorage.com`).
- `LITESTREAM_ACCESS_KEY_ID` / `LITESTREAM_SECRET_ACCESS_KEY` — the storage API credentials.

Render's **Build Command** should be `npm run build` (installs deps + downloads the Litestream binary) and the **Start Command** should be `npm start` (runs `start.sh`, which restores from the replica then launches the app under `litestream replicate`).

**Installing as a mobile app (PWA):** once the server is reachable at a real URL (not `localhost`), opening it on a phone offers "Add to Home Screen" (Android/Chrome) or Share → "Add to Home Screen" (iOS/Safari) — it then launches full-screen with its own icon, no app-store submission needed. This requires HTTPS in production (most hosts provide this automatically); it also works over plain HTTP on `localhost` for local testing.

Note: sessions are kept in memory, so logging in again is needed after a server restart. Fine for local use; swap in a persistent session store (e.g. Redis) for production. Also note: if an account's roles are changed while they're already logged in, their open browser tab picks up the new roles the next time it loads (it re-checks on page load) — an open Socket.io connection doesn't hot-swap mid-session.

Two default accounts are seeded on first run, both equally privileged:

- Username: `admin` — Password: `La00280424`
- Username: `miniplatform` — Password: `La00280424`
- Roles (both accounts): `is_staff: true`, `is_global_admin: true`

Both accounts' **Staff and Global Admin flags are permanently locked on** — they're how the very first role gets granted to anyone else, so they can never be unchecked. The Admin Panel shows their Staff checkbox as disabled with a 🔒, and the server independently ignores any attempt to turn it off (via the Admin Panel or a direct API call); their passwords can't be changed from My Account either. All of this is self-healing: it's re-applied on every server startup, so even if the database was edited by hand, restarting the server restores both accounts to Staff + Global Admin with the passwords above.

Use `admin` or `miniplatform` to grant roles from the Admin Panel (nav drawer → Admin Panel, visible to Staff accounts — not to a Global-Administrator-only account, since that role doesn't get panel access). The panel is search-first: nothing is listed until you type a username and search, so it stays usable with any number of registered accounts. Once you find a user, Staff can toggle any combination of seven roles — **Staff**, **Global Admin**, **Executive Board**, **Country Rep**, **Elite User**, **Mentor**, **Merchant** — plus set their level directly. To let an account kick people from rooms, give it the Global Administrator checkbox; the Kick button then appears for that account in every room's Participants panel.

## Project structure

```
src/
  server.js         — Express app, sessions, Socket.io wiring
  db.js             — SQLite schema + seed data (Node's built-in node:sqlite module), including room_memberships (persistent, decoupled from live sockets) and room_blocks (kick/bump rejoin cooldowns)
  auth.js           — session/role middleware + publicUser() shaping (adds derived level, xp progress, bio)
  level.js          — XP → level curve, level → XP curve, and XP reward amounts
  xp.js             — shared xp/level mutation + live socket push (used by both real-time play and the Admin Panel's level control)
  presence.js        — in-memory live room member counts + online-user tracking, shared between Socket.io and REST routes
  voucher.js         — per-room voucher spawn/expire/claim logic
  socket.js          — all real-time events: chat + gift/pick commands, gift shower, room members, kick, UNO, xp awarding, voucher auto-spawn
  game/uno.js         — UNO game engine (deck, turns, rules)
  routes/
    auth.js         — register/login/logout/me/bio
    rooms.js        — list/create/favorite rooms, recent rooms, message history
    gifts.js        — gift catalog
    admin.js        — user list, promote-to-admin, set-flags, set-level
    friends.js       — friend requests, accept/decline, list, remove
    alerts.js        — notification inbox
    messages.js       — private 1:1 "emails" inbox
    coins.js          — search + give-coins (Staff, Mentor, Merchant)
    members.js        — Explore → Members role groups + per-group listing
    leaderboard.js     — Leader Board / Legendary Contest / Gift Contest live rankings
    spin.js           — Daily Spin (24h cooldown, weighted prize table)
    colors.js         — Color Shop catalog + buy/reset
    avatar.js         — Avatar Maker options + frame/pet/scene update
    posts.js          — Announcements/Blog (shared "posts" table, staff-authored)
    giftstore.js       — Explore → Gift Store (send a gift to anyone, not just a room)
    users.js          — general username search (Gift Store's recipient picker)
public/
  index.html, app.js, styles.css  — single-page frontend (no build step)
data/
  app.db — created automatically on first run (SQLite)
```

A round that ends with everyone eliminated at once splits the pot evenly instead of cancelling it.

Tap it any time to expand it back, or to re-collapse it.

- **Personal coin/gift notices no longer leak into room chat.** Getting a "gave you 10000 coins" or "sent you a gift" ping now shows as a toast only — it used to get dropped into whatever room you happened to have open, which made it look like a room message.

- **New: the Legendary Bot dice-betting game**, in its own dedicated "Legendary Bot Official" room. Bet coins on one of six animals (Lion/Tiger/Fox/Wolf/Bear/Panda) using preset chips (500 up to 20k); Legendary Bot rolls 6 dice every round and pays out based on how many landed on your animal (0 matches loses the bet, 1 breaks even, up to 15x for a clean sweep). Fully server-authoritative — coins are escrowed the instant a bet is placed, the round timer runs independent of any one player's connection, and `!start` in that room kicks off a new round once the current one has finished (it also auto-restarts on its own if nobody types it). The whole game replaces the old UNO Arena concept, not a revival of it.

Pictures and short voice clips (6MB cap) upload straight from the browser and appear inline in chat — an `<img>` for pictures, a playable `<audio>` for voice notes.
- **The bot pool now fills every room immediately, and talks a lot more.** Every room gets an initial population of bots the moment the server starts (no more waiting on the slow drift simulation to spread 1000 bots across ~99 rooms one at a time), ambient chat now fires in batches every 2–4 seconds instead of one exchange every 20–75 seconds, bots occasionally drop a pure-emoji reaction instead of a text line, and the bot gift-shower simulation runs roughly 4x more often.
- **The app's default look is now a light/white theme**, not dark — every surface in the app (not just the page background) flips consistently between the two. Dark mode is still available and remembers your choice: turn it on from Settings → Dark Mode, no page reload needed.
- **UNO has been removed from this build entirely.** No Chat/UNO tabs in the room header, no Game List drawer entry, no UNO game logic on the server — every room (including the old "UNO Arena", kept only as a plain room name so nobody's old tab breaks) is just a regular chat room now. The Leader Board's "wins" category, previously UNO wins, now ranks by XP instead.

Each gets an auto-generated welcome description shown in its pinned room banner.
- **The bot pool is now ~1000 accounts** (up from 100), spread across all rooms via the existing ambient room-drift simulation, so rooms feel populated and active. All bots — new and existing — carry 5000 starting coins, topped back up automatically if a bot's balance ever runs low.
- **Bots now send gifts too, not just chat.** A new ambient "gift shower" simulation periodically picks a room with active bots and has one shower a capped, random handful of the others with a cheap gift — the same visible `/gift all`-style message and animation a real person's gift shower produces, paid for out of the sending bot's own balance.
- **New users — real signups and new bots alike — now start with 5000 coins** (was 1000 for real signups).
- **Room Settings is a full rebuild**, reached via ⋮ → Room Settings: a dedicated full-screen tabbed view (Settings / Moderators / Banned) with a back arrow, the room's name as a subtitle, and a top-right Save link. The Settings tab has three real, working controls: **Ghost Mode** (join a room without appearing in its member list — takes effect on your next join, applies instantly, no Save needed), a **Room Description** editor (500-character cap with a live counter — this is what the room's pinned welcome banner shows), and a **Lock Level** stepper (0–100; 0 shows an "Open to all" badge; anyone below the room's lock level is turned away on join with a clear message). Staff, Global Admin, and a room's owner can edit Description/Lock Level and manage bans; Room Silence (existing feature) moved into this same screen, still usable by moderators too.

The Participants panel has a new "Ban" button (same permission tier as Room Settings), the Banned tab lists everyone currently banned from that room with a one-tap Unban, and a banned user is turned away on any attempt to rejoin until they're unbanned.
- **Multi-room chat no longer disappears when you switch tabs.** Fixed for good this time: with several room tabs open, flipping between rooms you're already in (Room A → Room B → back to Room A) now preserves each room's live chat exactly as it was, via a per-room, this-session client-side cache (`roomMessageCache`). Only a genuine Leave Room, a kick, a bump, or the 5-hour idle timeout clears a room's chat — those still start it blank on the next real entry, as before.

Chat rooms never show the UNO tab or the UNO entry in the Game List, and the server independently rejects any attempt to start/join a UNO lobby in a chat room — the only way to play UNO is to go to a game room. Game-room cards show a 🎮 badge in Room Browser for easy discovery.
- **Gift Shower coins are deducted from the sender for everyone, no exceptions.** Verified this already worked correctly for every role including Staff and Global Admin (sending `/gift all` deducts `gift cost × recipient count` from the sender's own balance every time) — confirmed with a live test rather than just a code read, since this was specifically called out as a concern.

A moderator's username renders in yellow in chat and the Participants panel (with a 🔰 badge), the same way Global Admin's does. This backfills automatically on any existing database too (no reset needed), and replaces the older single "Sudan" gift with this cheaper, always-first version.

## Notes & next steps

- This is a self-contained build, not a byte-for-byte clone of mig66 — it reproduces the visual layout and core mechanics (home screen, room browser, chat, gifts, vouchers, UNO, leveling, staff/admin roles, room moderation, alerts/emails/friends, the Explore hub and everything under it) with original code, art, and branding.
- Two deliberate simplifications from the reference app, both called out where they're implemented above: **Contests** (Legendary/Gift) are always-on live rankings by lifetime totals, not time-boxed events with resets and separate payouts; **Avatar Maker** is a frame-color + pet-emoji + scene-emoji picker, not a full layered-outfit/clothing compositor with an inventory.
- Avatars are colored-initial circles/squares (deterministic color derived from the username or room name) rather than photo uploads, per the "keep it simple" direction.
- A kicked user isn't banned — they can rejoin the room immediately from the Room Browser. Let me know if you want an actual timed or permanent ban instead.
- The database is SQLite (via Node's built-in `node:sqlite`) for simplicity; swap it for Postgres/MySQL if you need to scale beyond a single server.
- Passwords are hashed with bcrypt; sessions are currently kept in memory (see note above).
- For production, set a strong `SESSION_SECRET` environment variable, use a persistent session store, and serve behind HTTPS.
